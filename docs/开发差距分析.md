## 二、第一梯队（已全部完成 · 2026-11-14）

**完成与验证情况**（真机 KEE-AL00，日志与截屏为证）：

| 项 | 结果 | 关键证据 |
|---|---|---|
| 通知栏一键停止 | ✅ | 通知展开出现「停止拦截」按钮；点击后日志 `notification stop button tapped` → `stop from notification ok` → `VPN onDestroy` → `STATS (onDestroy)` |
| 首页真实状态 | ✅ | 冷启动读 `vpn_state.json` 显示「已停止」；启动成功写 `running=true`；创建失败写 `errCode` 显示「异常」；3 秒轮询兜住通知中心 overlay 不触发 `onPageShow` 的场景 |
| AUTO_STOP 对齐 | ✅ | 删除 2 分钟自停与 `AUTO_STOP_MS`，改为常驻直到手动停止（§10-3） |
| 规则文件化 / 热更新 | ✅ | 扩展日志 `RuleStore loaded black=16 white=13 allow=0`；主进程写放行后扩展 `RuleStore reloaded ... allow=1`，**未重启 VPN、未重新编译** |
| 本次放行 | ✅ | 诊断页输入 → `session allow + adx.sogaha.cn`；停止时 `RuleStore session allow cleared`；判定逻辑抽为纯函数 `decideWithSessionAllow` 并补 7 项单测 |
| AAAA `::` 应答 | ✅ | 真机日志 `BLOCK adx.sogaha.cn qt=28 ans=AAAA(::)`；单测 10 项覆盖 TYPE=28 / RDLENGTH=16 / 全 0 |
| 空闲降频 | ✅ | `readLoop` 连续 EAGAIN 由 10ms 退避到 100ms，读到包立即回 10ms（代码级 + 编译验证） |
| 文档债 | ✅ | README 全面重写；手册加「V1–V6 已实现」状态横幅、修正「抓到即销毁」与风险告知 |

⚠️ 验证中修掉一个真实缺陷：旧 `stopVpn()` 在 `await fwd.stop()`（内部 `await udp.close()`）挂住，导致 `onDestroy` 后进程被回收，状态文件写不成、通知残留、首页显示假的「运行中」。已改为**同步优先收尾**（状态／通知／统计／清空放行）+ 网络资源 fire-and-forget。

**单测**：135 → **152 项全过**（DnsCodec 76 / DomainRules 48 / DiagStats 28）；HAP 编译通过并装机验证。

## 五、需要产品侧决策的三处矛盾

1. **R-11 vs FR-4.1／FR-5.2**：DNS 层拿不到请求方包名，「按 App 归集 + 效果分级」在当前架构下不可能自动实现。建议改成「手动选择本次测试 App 标签」再归集，或删除该需求。
2. **AUTO_STOP 2 分钟 vs §10-3「连续 24 小时不自动断开」**：正面冲突。本轮按 §10-3 改为常驻手动停止。
3. **FR 分组 vs 迭代路线**：FR-3.4/3.5、FR-8.x 标为 P0，§9.2 却划「不含」，而 §10-7 强制要求热更新。建议按 §10 验收反推优先级，统一标注一次。
