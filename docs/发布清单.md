## 附录 A：AppGallery 数据安全表单填写模板

> 说明：下表为模板，**须按本应用真实行为如实填写**，开发者对声明真实性负责。本应用的核心事实是「**所有 DNS 处理均在设备本地完成，不上传任何服务器，不与任何第三方共享**」。

| 表单问题（意译） | 推荐填写 | 依据 |
|---|---|---|
| 是否涉及个人数据处理？ | **是（仅本地）**——应用处理设备发出的 DNS 查询（域名），属「网络日志/浏览信息」类个人信息 | VPN/DNS 拦截必然接触域名 |
| 收集哪些个人信息类型？ | 网络日志（DNS 查询域名、查询时间）；**不收集**设备标识符、联系人、位置、相册等 | 见 `核心/DnsCodec`、`net/UpstreamForwarder`：仅按协议转发至可配置上游 |
| 数据处理目的 | 在设备本地识别并拦截开屏广告域名，提升使用体验 | 应用功能本身 |
| 是否上传/传输到服务器？ | **否**——DNS 查询仅按 Do53 转发至用户**可配置**的上游解析服务器（默认公共 DNS），不经过开发者服务器；诊断统计、规则文件均存于设备本地 | `docs/隐私政策.md` + 代码 |
| 是否与第三方共享？ | **否**——不与任何第三方共享任何数据 | 无上报/无 SDK |
| 数据存储位置与期限 | 仅设备本地（`rules.json`、诊断缓存）；用户卸载即清除 | `config/RuleStore`、`common/*State` |
| 用户权利如何保障 | 提供规则导入/导出（用户可查看/备份/删除全部数据）；随时可在系统中停止 VPN 权限 | `pages/Rules.ets` 导入导出 |
| 是否含儿童个人信息 | 否 | 工具类应用 |
| 是否加密传输 | DNS 转发走标准协议；如需可配置 DoH/DoT（规划中） | `docs/开屏广告屏蔽方案系统分析.md` |

> 关键点：AppGallery 对「是否在后台收集/上传」审查很严。**本应用若如实声明「不上传、本地处理」，是最稳妥的口径**；切勿为过审而隐瞒功能，也不要夸大收集范围。
